# Protocol decisions (details the approach paper leaves open)

The approach paper (`Team_10-1.pdf`) is the source of truth. The decisions below fill gaps it leaves
open. Each one is implemented in code (file in brackets). Both authors should sign off before the
full run. Changing any of them later means rebuilding the scenario bank.

| # | Decision | Choice | Rationale |
|---|---|---|---|
| D1 | **Models** | Local: `llama3.1:8b-instruct-q4_K_M` (Llama-3.1-8B-Instruct, Q4_K_M) via Ollama. Closed API: **xAI Grok**, exact model id pinned at launch and logged per call. [`config.py`, `run/clients.py`] | Paper requires a 7–9B open-weight model plus a closed API model from a different family. The earlier Gemini → Groq choice is replaced by xAI, the API the team has access to. Llama (Meta) and Grok (xAI) are distinct families (H5). |
| D2 | **Baseline cell quota** | No message; 4 paraphrases × 4 replicate slots × 3 samples = 48 decisions/cell, the same as factorial cells. [`build_scenarios.py`] | Keeps baseline precision equal to factorial cells; 110 × 48 = 5,280 as in the paper. |
| D3 | **Message rotation** | Within each emotion, cells are numbered k = 0..19 in a fixed order. Cell k omits message variant (k mod 5); the other 4 are fully crossed with the 4 paraphrases (16 variants). S2 UG and DG cells at the same stakes share k, so the same message subset is used. [`build_scenarios.py`] | Balanced use of every message (204–216 trials each); H4 Game contrast not confounded with message subset. |
| D4 | **Output format** | Schema-constrained JSON on both providers. Keys: `decision` (`accept`/`reject`), `give`, `return`, `send` (integer INR); checks: `emotion`, `intensity`, `fairness`, `p_retaliate`. [`run/runner.py`] | Removes parsing ambiguity; amounts in INR, converted to shares in analysis. |
| D5 | **Justification subset** | `reason` field requested on a seeded random 20.0% of trials, placed **after** the decision key. `justify` is stored so it can be tested as a covariate. [`build_scenarios.py`] | Paper: one-line justification on a random 20% subset. Placing the reason after the decision stops it acting as chain-of-thought before the choice. |
| D6 | **Response-option order** | S1: order of "accept"/"reject" randomised per trial, in both the question and the JSON enum. Checks: the order of the four emotion labels is randomised. Numeric games have no options. [`build_scenarios.py`] | Paper control: randomised response-option order. |
| D7 | **Off-format / refusals** | Every attempt is logged with a status (`ok`, `off_format`, `out_of_range`, `refusal`, `error`). Failed trials are re-asked with a new seed, up to 3 attempts in total. Analysis uses the first valid attempt. First-attempt failure rates are reported per model × sub-experiment. Trials that fail all 3 attempts are reported as missing. [`run/runner.py`, `analysis/common.py`] | Paper: "refusals and off-format outputs logged and reported, never silently dropped". |
| D8 | **Seeds** | Master seed 20260912. Every per-trial random draw (justification flag, option order) and the model sampling seed come from SHA-256(master seed, trial id). [`build_scenarios.py`] | Full reproducibility of the bank; samples within a variant differ through their seeds. |
| D9 | **Trial order** | Prompt-variant groups shuffled with a fixed seed. The 3 samples of a variant run back to back. [`run/runner.py`] | No confound between time of run and condition; adjacent identical prefixes let the local runtime reuse its KV cache, which does not affect outputs. |
| D10 | **Manipulation / belief checks** | Separate calls. Each uses the same scenario text and message as a decision trial, but asks the questions in place of the decision. 4 variants per factorial cell (one per paraphrase, message rotating) and 2 per baseline cell gives 396 calls/model, 792 in total. Emotion and intensity are skipped for baselines (no message). Fairness is asked only where the counterpart made an allocation to the model (S1, S3a). `p_retaliate` asks: "if your decision were unfavourable to the counterpart, how likely (0–100) would they reject or retaliate if given the chance". [`build_scenarios.py`] | Paper: checks on a sampled subset, about 800–1,000 calls; recognition summarised by confusion matrices. |
| D11 | **Ceiling/floor rule for the fallback** | After the pilot, a model is at **ceiling** if P(reject \| 10% offer) ≤ 0.10, and at **floor** if P(accept \| 50% offer) ≤ 0.10, pooled over emotions and stakes. If either model meets either rule: (i) add the 5% and 45% offer cells (`build_scenarios.py --fallback`; +20 cells, +960 trials per model) for **both** models, and (ii) use the log-probability DV where the runtime returns logprobs. | Paper's pre-registered fallback, made operational. Applied to both models to keep the design identical. |
| D12 | **Stakes and shares** | Stakes are effect-coded (−0.5 = INR 100, +0.5 = INR 10,000). S2 share = give/pie. S3a share = returned / tripled amount received. S3b share = sent / endowment. S1 offer centred at 30% in the GLMM. | Coefficients then read as effects at the middle of the design. |
| D13 | **Temperature** | 1.0 for all main runs; 0.7 robustness subset (S1 only) if time allows (Nov 1–7). | As in the paper. |
| D14 | **Message screening** | Automatic screen (`stimuli/freeze_messages.py`): 18–25 words; no emotion label words; no accept/reject/retaliation or game-move words (offer, split, give, keep, return, send, fair, …); no money/financial-need content, since need would confound sadness. 5 per emotion are then selected: by peer ratings once `stimuli/peer_ratings.csv` exists, otherwise by closeness to the mean length (current **provisional** freeze). | Paper: length-matched, emotion conveyed through content, no stated intent to accept/reject/retaliate. |

## Status of the stimulus freeze

`stimuli/messages_frozen.csv` is currently a **provisional** freeze: all 20 messages passed the
automatic screen and were chosen for length matching (mean 21.4–22.6 words per emotion). The ~10-peer
rating has not been run. When it has, put the responses in `stimuli/peer_ratings.csv` and rerun
`python stimuli/freeze_messages.py && python build_scenarios.py`. Any change to the frozen set
requires rebuilding the scenario bank, and **must happen before the main run**.
